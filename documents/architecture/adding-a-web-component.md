# Adding a Grove web component

This guide covers everything needed to ship a new Grove web component, `grove-<name>`, to all three ways consumers use it:

- **npm**: `import "@newjersey/njwds/web-components/grove-<name>"`
- **React**: `import { Grove<Name> } from "@newjersey/njwds/react"`
- **CDN**: the `web-components/grove.min.js` bundle

`grove-divider` (`packages/njwds/src/web-components/grove-divider/`) is the reference implementation. Paths below are relative to `packages/njwds/` unless they start with the repo root.

## Before you start

- **Should this be a web component?** Per `documents/decisions/general.md`, only build one when it adds behaviour beyond a base HTML element. Otherwise, ship a `.grove-<name>` CSS class. (`grove-divider` is the exception: it piloted the pipeline.)
- **Names are public API.** Once released, renaming any of these is a breaking change:
  - the tag (`grove-<name>`)
  - the exported class (`Grove<Name>`)
  - CSS custom properties (`--grove-<name>-*`)
  - attributes, properties and events
  - any file path in `dist/` (the package's `"./*"` export makes every file importable)

  Pick them carefully.

## Names

Every template in this guide uses three forms of the component's name, plus one for events. Example values are for a component called "date picker":

| Placeholder | Form | Example | Used for |
|---|---|---|---|
| `<name>` | kebab-case, without the `grove-` prefix | `date-picker` | tag (`grove-<name>`), file names, the component folder, `src/tests/components/<name>/`, CSS class and custom properties, story ids |
| `<Name>` | PascalCase | `DatePicker` | class and React export (`Grove<Name>`), story folders (`src/stories/*/<Name>/`) |
| `<Title>` | sentence case words | `Date picker` | story titles (`Web Components/<Title>`), Playwright `suiteName` |
| `<event>` | kebab-case | `change` | DOM event `grove-<event>` |

- Storybook derives a story id from the title by lowercasing it and turning spaces into hyphens. So `Web Components/Date picker` + `export const Default` gives **`web-components-date-picker--default`**, which is `web-components-<name>--default`. Use sentence case for titles, as the existing stories do (`Components/Summary box` → `components-summary-box--default`). A PascalCase title like `DatePicker` would give `datepicker` and break the Playwright URLs.
- Theming properties: `--grove-<name>-<css-property>`. Add `-<part>`/`-<state>` only when needed, and never a breakpoint name.

## What happens automatically

You don't edit any build config, `package.json`, or workflow to add a component. Creating `src/web-components/grove-<name>/` with an `index.ts` is enough for all of this:

| Output | Generated by |
|---|---|
| `dist/web-components/grove-<name>/index.js` (+ `.d.ts`) | `vite.config.grove.ts` discovers every `grove-*` folder (`build-scripts/web-components.ts`) |
| Root `index.js` / `index.d.ts` re-export | `build-scripts/vite-plugin-njwds-assets.ts` |
| `@newjersey/njwds/react` export of your wrapper (+ `dist/react/index.d.ts`) | `build-scripts/vite-plugin-grove-react-entry.ts` |
| Inclusion in the CDN bundle `dist/web-components/grove.min.js` | `vite.config.grove-cdn.ts` |
| `package.json` `exports` / `sideEffects` coverage | `./web-components/*` and `**/web-components/**` already match |
| CDN upload and SRI hash | `publish-release.yml` mirrors `dist/` and hashes `web-components/*.js` |

## Files to create

```
src/web-components/grove-<name>/
├── index.ts                     # build entry + public surface
├── grove-<name>.ts              # the element
├── grove-<name>.scss            # styles (shadow DOM, optionally the global class too)
├── grove-<name>.react.ts        # React wrapper (required: a test fails without it)
├── grove-<name>.spec.ts         # behaviour tests
└── grove-<name>.react.spec.ts   # React render smoke test
src/stories/web-components/<Name>/<Name>.stories.ts
src/stories/react-components/<Name>/<Name>.stories.ts
src/stories/components/<Name>/<Name>.stories.ts           # only if there's a CSS-only version
src/tests/components/<name>/visual/<name>.visual.spec.ts
src/tests/components/<name>/accessibility/<name>.accessibility.spec.ts
```

Only edit an existing file if the component has a CSS-only version: `src/sass/_uswds-theme-custom-styles.scss` (step 3).

### Import rules (enforced by ESLint inside `src/web-components/`)

- **Relative imports only**, no `@`, `@web-components` or `@stories` aliases. `tsc` copies import paths into the published `.d.ts` files, where aliases can't be resolved.
- **Relative imports need a `.js` extension** (`"./grove-<name>.js"`, which resolves to the `.ts` file). Without it, `node16`/`nodenext` TypeScript consumers get `TS2834`, or silently untyped components. The only exception is `?inline` stylesheets (`"./grove-<name>.scss?inline"`).
- Shared helpers go in `src/web-components/shared/`, a folder without the `grove-` prefix so it isn't treated as a component.

These apply to the specs in that folder too. Stories and Playwright tests live outside it, so they may use aliases.

## Step 1: The element (`grove-<name>.ts`)

```ts
import { LitElement, html, unsafeCSS } from "lit";
import { property } from "lit/decorators.js";
import { defineElement } from "../shared/define-element.js";
import hostStyles from "../web-styles.scss?inline";
import sheet from "./grove-<name>.scss?inline";

export class Grove<Name> extends LitElement {
  static override styles = [unsafeCSS(hostStyles), unsafeCSS(sheet)];

  /** Visual variant. Reflected so it can be styled and set from HTML. */
  @property({ reflect: true }) variant: "default" | "emphasis" = "default";

  override render() {
    return html`<div class="grove-<name>">…</div>`;
  }
}

defineElement("grove-<name>", Grove<Name>);

declare global {
  interface HTMLElementTagNameMap {
    "grove-<name>": Grove<Name>;
  }
}
```

- **Register with `defineElement`, not `@customElement`.** It's a no-op if the same class is already registered. If a *different* copy of Grove got there first (for example the CDN bundle plus an npm copy on the same page), it warns instead of throwing.
- **`web-styles.scss`** supplies the shared `:host` defaults: `display: block`, and `display: none` when `hidden` is set. Without it, custom elements default to `display: inline`. If you override `:host` display, keep the `[hidden]` rule.
- **Keep `HTMLElementTagNameMap`.** It types `document.createElement("grove-<name>")` and `querySelector`.
- **`@property`** works with this repo's TypeScript settings (`experimentalDecorators: true`, `useDefineForClassFields: false`, Lit's documented setup). `grove-divider` has no properties, so the first component with props will be the first to use it. Check that it behaves as expected in your spec.
- **Events:** dispatch with `new CustomEvent("grove-<event>", { bubbles: true, composed: true, detail })`. `composed: true` lets the event cross the shadow boundary.
- **Accessibility in Shadow DOM:**
  - `aria-labelledby`/`aria-describedby` can't point at an id on the other side of the shadow boundary.
  - Interactive components need real keyboard support, and Playwright keyboard tests for it (see step 6).
  - Form-like components need `ElementInternals` to take part in a surrounding `<form>`.

## Step 2: Styles (`grove-<name>.scss`)

```scss
@use "../../sass/uswds-theme"; // Grove's own Sass: always a relative path
@use "uswds-core" as *;        // USWDS modules: bare names only

.grove-<name> {
  color: var(--grove-<name>-color, #{color("ink")});
}
```

- **Relative paths for Grove's Sass, bare names only for USWDS modules.** Consumers compile with only the USWDS load path, so a bare Grove name breaks their build. `build-scripts/sass-consumer.spec.ts` compiles every component stylesheet that way and will fail.
- **Theming:** expose `--grove-<name>-<css-property>` with the default as the fallback. Custom properties cross the shadow boundary; responsive defaults stay internal.
- **No shadow-only CSS here** (`:host`, `::slotted`) if the file is also forwarded into the global stylesheet (step 3). Put that CSS in the component, or in `web-styles.scss` if it's shared.

## Step 3: Global CSS class (only if there's a CSS-only version)

If the component also ships as a plain `.grove-<name>` class, as the divider does with `<hr class="grove-divider">`, add a `@forward` to `src/sass/_uswds-theme-custom-styles.scss`. It goes in the block under the `// web component imports` comment, which holds one line per component (alphabetical), after the USWDS theme forwards:

```scss
@forward "../web-components/grove-<name>/grove-<name>";
```

The same `.scss` is then compiled twice: once as the shadow stylesheet and once into `dist/css/styles.css`. That's why it must stay context-neutral (step 2).

## Step 4: Entry and React wrapper

`index.ts` is the build entry and the component's public surface:

```ts
export { Grove<Name> } from "./grove-<name>.js";
```

**`index.ts` must never import the React wrapper, directly or indirectly.** It's what non-React consumers load. `build-scripts/react-wrappers.spec.ts` fails if `react` or `@lit/react` is reachable from it.

`grove-<name>.react.ts`:

```ts
import * as React from "react";
import { createComponent, type EventName } from "@lit/react";
import { Grove<Name> as Grove<Name>Element } from "./grove-<name>.js";

// React wrapper, published only through @newjersey/njwds/react. index.ts must never
// import this file, or React would reach every web component consumer.
export const Grove<Name> = createComponent({
  tagName: "grove-<name>",
  elementClass: Grove<Name>Element,
  react: React,
  // Only for components that dispatch events: React prop name → DOM event name
  events: {
    ongrove<event>: "grove-<event>" as EventName<CustomEvent<{ /* detail */ }>>,
  },
});
```

- The export takes the element class's name, and the class is imported under an alias.
- `build-scripts/react-wrappers.spec.ts` fails if a `grove-*` folder has no `<tag>.react.ts`.
- `@lit/react` passes props to the element as **properties**, so React consumers can pass objects and arrays.

## Step 5: Unit tests (colocated, jsdom)

These run in the `unit` Vitest project with `npm run test` / `test:coverage`.

**`grove-<name>.react.spec.ts`:** renders the wrapper with `react-dom/client` + `act`. That catches a wrong `tagName`, which still type-checks but renders an empty element. The shadow DOM assertion on the last line must match something the element actually renders (here, the `div.grove-<name>` from step 1). If you change the element's markup, change this selector too, or the test fails with `expected null not to be null`.

```ts
/**
 * Render smoke test for the grove-<name> React wrapper
 *
 * A wrapper with the wrong tagName still type-checks, but renders an unregistered,
 * empty element. Rendering through react-dom proves the wrapper produces the real,
 * upgraded <grove-<name>> with its shadow DOM.
 */
import { afterEach, describe, expect, test } from "vitest";
import { act, createElement } from "react";
import { createRoot, type Root } from "react-dom/client";
import { Grove<Name> } from "./grove-<name>.react.js";
import type { Grove<Name> as Grove<Name>Element } from "./grove-<name>.js";

// Tells React this environment supports act(), so it doesn't warn on every update
(globalThis as { IS_REACT_ACT_ENVIRONMENT?: boolean }).IS_REACT_ACT_ENVIRONMENT = true;

describe("Grove<Name> (React wrapper)", () => {
  let container: HTMLElement;
  let root: Root;

  afterEach(() => {
    act(() => root.unmount());
    container.remove();
  });

  test("renders a registered <grove-<name>> with its shadow DOM", async () => {
    container = document.createElement("div");
    document.body.appendChild(container);
    root = createRoot(container);

    act(() => root.render(createElement(Grove<Name>)));

    const element = container.querySelector("grove-<name>");
    expect(customElements.get("grove-<name>")).toBeDefined();
    expect(element).toBeInstanceOf(customElements.get("grove-<name>")!);
    await (element as Grove<Name>Element).updateComplete;
    expect(element!.shadowRoot!.querySelector("div.grove-<name>")).not.toBeNull();
  });
});
```

**`grove-<name>.spec.ts`:** behaviour tests for the element itself:

```ts
import { afterEach, describe, expect, test } from "vitest";
import "./index.js";

afterEach(() => {
  document.body.innerHTML = "";
});

describe("<grove-<name>>", () => {
  test("reflects variant to the attribute", async () => {
    const el = document.createElement("grove-<name>");
    document.body.append(el);
    el.variant = "emphasis";
    await el.updateComplete;
    expect(el.getAttribute("variant")).toBe("emphasis");
  });
});
```

- Test real behaviour: properties ↔ attributes, rendered shadow DOM, events dispatched (and `composed`), keyboard handling.
- **Output must be clean.** If a test triggers a warning or error on purpose, spy on it, assert on it, and keep it out of the output.
- Coverage thresholds (80%) include `src/web-components/**`. Uncovered component code can fail `test:coverage` even when every test passes.

## Step 6: Storybook stories and Playwright tests

**Web component story:** `src/stories/web-components/<Name>/<Name>.stories.ts`. Import through the folder, so the story uses the same public surface consumers get:

```ts
import type { Meta, StoryObj } from "@storybook/web-components-vite";
import { html } from "lit";
import "@web-components/grove-<name>";

const meta = {
  title: "Web Components/<Title>",
  tags: ["autodocs"],
  args: { variant: "default" },
  render: ({ variant }) => html`<grove-<name> variant=${variant}></grove-<name>>`,
} satisfies Meta;

export default meta;
type Story = StoryObj;

export const Default: Story = {};
export const Emphasis: Story = { args: { variant: "emphasis" } };
```

**React story:** `src/stories/react-components/<Name>/<Name>.stories.ts`.
- This Storybook renders web components, so mount the wrapper with `react-dom`, and set the "Show code" snippet by hand. Otherwise it shows `<div></div>`.
- Keep the React file to what's React-specific: basic usage, props, events. The variants live in the web component file.

```ts
import type { Meta, StoryObj } from "@storybook/web-components-vite";
import { createElement } from "react";
import { createRoot } from "react-dom/client";
import { Grove<Name> } from "@web-components/grove-<name>/grove-<name>.react";

const meta = {
  title: "React Components/<Title>",
  tags: ["autodocs"],
  render: () => {
    const container = document.createElement("div");
    createRoot(container).render(createElement(Grove<Name>));
    return container;
  },
  parameters: {
    docs: {
      description: { component: '`import { Grove<Name> } from "@newjersey/njwds/react";`' },
      source: { code: "<Grove<Name> />", language: "tsx" },
    },
  },
} satisfies Meta;

export default meta;
type Story = StoryObj;

export const Default: Story = {};
```

- **CSS-only story** (only with step 3): `src/stories/components/<Name>/<Name>.stories.ts`, titled `Components/<Title>`, rendering the plain markup with the class.
- Every story export also runs as a Vitest browser test (`@storybook/addon-vitest`), but that only proves "renders without throwing". Behaviour is tested in step 5.

**Playwright suites** (`src/tests/components/<name>/`). They run against Storybook story ids, derived from the title (see [Names](#names)), e.g. `web-components-<name>--default`:

```ts
// visual/<name>.visual.spec.ts
import { runVisualSuite } from "../../../../utils/runVisualSuite";

runVisualSuite({
  suiteName: "<Title>",
  cases: [
    { name: "Default (Web Component)", url: `/iframe.html?id=web-components-<name>--default&viewMode=story` },
    { name: "Default (React)", url: `/iframe.html?id=react-components-<name>--default&viewMode=story` },
  ],
});
```

```ts
// accessibility/<name>.accessibility.spec.ts
import { runA11ySuite } from "../../../../utils/runA11ySuite";

runA11ySuite({
  suiteName: "<Title>",
  include: "#root-inner",
  cases: [
    { name: "Default (Web Component)", url: `/iframe.html?id=web-components-<name>--default&viewMode=story` },
    { name: "Default (React)", url: `/iframe.html?id=react-components-<name>--default&viewMode=story` },
  ],
});
```

- Generate the visual baselines with Storybook running (`npm run storybook`), using `npm run test:visual:update`. Commit the new files under `src/tests/__screenshots__/components/<name>/`.
- **Interactive components:** axe can't verify keyboard behaviour. Add a Playwright spec next to these that tabs to the component and operates it with the keyboard (Enter/Space/Escape/arrows as appropriate), asserting focus and state. WCAG 2.2 AA is required.
- Locally, run the suites against a warmed-up or static Storybook. A cold dev server can fail most tests while it compiles stories. CI uses a static build.

From the repo root:

```bash

grep "grove-<name>" index.js dist/react/index.d.ts   # root entry + React types
grep -c "grove-<name>" dist/web-components/grove.min.js   # > 0: it's in the CDN bundle
```

**CDN smoke test:** open a plain HTML file in a browser, from anywhere outside the repo:

```html

<grove-<name>></grove-<name>>
```

It should render with no console errors. The bundle is a classic script with Lit included, so it needs no server or build step.

**Packaging checks (recommended for the first few components):** run `npm pack` from a **clean checkout** of the branch, because a working `dist/` may hold stale files. Install the tarball into a scratch Vite app, and into a React app with `@lit/react`, outside the repo, and confirm the component renders and type-checks. If the change touches anything beyond the new folder, also confirm no existing package file disappeared.

## Releasing

- A new component is a **minor** version (new files only). Changing an existing component's tag, properties, events, custom properties, or any `dist/` path is **major**.
- Nothing extra is needed for the CDN: the bundle includes the new component, and the release notes and `sri-hashes.txt` already cover `web-components/grove.min.js`.

## When a guard fails

| Failure | Cause | Fix |
|---|---|---|
| Build: `…grove-<name> is missing index.ts` | a `grove-*` folder without an entry | add `index.ts`, or rename a helper folder so it doesn't start with `grove-` |
| `react-wrappers.spec.ts`: `grove-<name> has a React wrapper` | no `grove-<name>.react.ts` | add the wrapper (step 4) |
| `react-wrappers.spec.ts`: `…entry can't reach React` | `index.ts`, or something it imports, imports the wrapper or React | remove that import |
| `sass-consumer.spec.ts` | a bare Grove Sass name, or `:host` in a forwarded stylesheet | use a relative `@use`; move shadow-only CSS into the component |
| ESLint `no-restricted-imports` | an alias, or a missing `.js` extension, in `src/web-components/` | use a relative path with `.js` |
| Console: `<grove-<name>> is already registered by a different class` | two copies or versions of Grove on one page (expected to warn, not throw) | load one copy |

## Scaffolding script specification

A script to generate a new component doesn't exist yet. This section defines what it should do, so it can be built from this guide alone. The templates in steps 1–6 are the source of truth for file contents; this section covers inputs, derived values, which files to write, and how to prove the output works.

### Inputs and validation

- **Required:** `<name>`, kebab-case without the prefix (`date-picker`). Validate against `^[a-z][a-z0-9]*(-[a-z0-9]+)*$`.
- **Reject:**
  - a name that is `shared` (reserved for helpers)
  - a name whose folder `src/web-components/grove-<name>/` already exists
  - any run where a target file already exists. Never overwrite.
- **Options:**
  - `--title "<Title>"` overrides the derived title, for acronyms or brand words (e.g. `faq-list` should be `FAQ list`, not `Faq list`)
  - `--css-class` adds the CSS-only version: the global `@forward`, a `Components/<Title>` story, and a `Default` Playwright case pointing at it

### Derived values

| Value | Rule | `date-picker` gives |
|---|---|---|
| `<Name>` | split on `-`, capitalise each part, join | `DatePicker` |
| `<Title>` | split on `-`, join with spaces, capitalise the first letter only (unless `--title`) | `Date picker` |
| story ids | `toId(title, exportName)` from `storybook/internal/csf`; don't reimplement it | `web-components-date-picker--default`, `react-components-date-picker--default` |

The `toId` outputs above were checked against Storybook 10.6.5's own function.

### Files to write

All paths are relative to `packages/njwds/`.

| Path | Template | When |
|---|---|---|
| `src/web-components/grove-<name>/grove-<name>.ts` | step 1 | always |
| `src/web-components/grove-<name>/grove-<name>.scss` | step 2 | always |
| `src/web-components/grove-<name>/index.ts` | step 4 (entry) | always |
| `src/web-components/grove-<name>/grove-<name>.react.ts` | step 4 (wrapper) | always; omit the `events` block unless the component has events |
| `src/web-components/grove-<name>/grove-<name>.spec.ts` | step 5 (element spec) | always |
| `src/web-components/grove-<name>/grove-<name>.react.spec.ts` | step 5 (React spec) | always |
| `src/stories/web-components/<Name>/<Name>.stories.ts` | step 6 (web component story) | always |
| `src/stories/react-components/<Name>/<Name>.stories.ts` | step 6 (React story) | always |
| `src/stories/components/<Name>/<Name>.stories.ts` | step 6 (CSS-only story) | `--css-class` |

**The only edit to an existing file, and only with `--css-class`:** insert `@forward "../web-components/grove-<name>/grove-<name>";` into `src/sass/_uswds-theme-custom-styles.scss`. It goes in the block under the `// web component imports` comment, keeping the block alphabetical. If that comment isn't found, fail with a clear error instead of guessing where to put it.

Nothing else changes. Build config, `package.json`, the `/react` entry, the CDN bundle and the release workflow all pick the component up automatically (see [What happens automatically](#what-happens-automatically)).

### After writing

1. **Run Prettier on every written file** (`npx prettier --write <files>`). Some template lines are longer than the repo's Prettier width, and CI runs `format:check`.
2. **Print the next steps:**
   - implement the element and its tests (the templates are placeholders: a sample `variant` property and `<div>` markup)
   - run `npm run storybook`, then `npm run test:visual:update`, to create the screenshot baselines
   - add keyboard tests if the component is interactive
   - run the step 7 checks

### Acceptance test for the script

The script works if, run in a clean checkout with **no manual edits** to its output:

- `npx eslint` on the generated paths passes (the alias and `.js` extension rules).
- `npx tsc --noEmit -p tsconfig.json` passes.
- These pass in the `unit` project:
  - `npx vitest run --project unit src/web-components/grove-<name> build-scripts/react-wrappers.spec.ts build-scripts/sass-consumer.spec.ts`
- These pass in the `storybook` project:
  - `npx vitest run --project storybook src/stories/web-components/<Name> src/stories/react-components/<Name>`
- `npm run grove:build` succeeds, and then:
  - `dist/web-components/grove-<name>/index.js` exists
  - `index.js` and `dist/react/index.d.ts` mention `grove-<name>`
  - `dist/web-components/grove.min.js` contains `grove-<name>`
- `npm run format:check` passes.

The Playwright visual suite is **expected to fail** until baselines are generated. That's a manual step, not a script bug.

These templates were checked by hand on 2026-11-09 by generating `grove-example` exactly as written. ESLint, tsc, both unit specs, both guard specs and `grove:build` (including the CDN bundle) all passed. The story tests weren't run, because the throwaway worktree couldn't run any story tests, including the existing divider's. Run them in a normal checkout.

### Building the script

- **No new dependencies** without approval: use Node's `fs`/`path` plus what's already installed (Prettier, Storybook's `toId`).
- **Test it like `build-scripts/`:** unit tests for name validation, name and title derivation, and the file list, using temporary directories (see `build-scripts/web-components.spec.ts`). Plus one end-to-end run of the acceptance test above.
- When it ships, update CLAUDE.md's "There is no component scaffolding/generator" line, and this section.

### Open decisions (decide before building)

- **Location and command name:** for example `build-scripts/new-component.ts` run through a `new-component` npm script. Remember that imports from Vite configs into `build-scripts/` keep their `.ts` extension.
- **Default template content:** keep the sample `variant` property and its spec (they show the pattern, and keep coverage up), or generate a bare element?
- **React event prop names for multi-word events:** `grove-value-change` can't simply become `ongrove<event>`, because the dashes don't make a valid identifier. It could be `ongrovevaluechange` or `onGroveValueChange`. Pick one convention before the first component with events ships, because React prop names are public API.
- **A `grove-` prefix in the input:** reject it, or strip it with a warning?
